\subsection{Functional Requirements}

\begin{itemize}
    %we thought that student look for an internship in two methods: 1 search by keyword 2 use recommendation (which appears in home page)
    %convert all in must, should 

    \item The system must permit students to register by providing their personal information and an institutional email\footnote{This is the email assigned to the student by their university.}.%specify differences in registrations.
    \item The system must permit companies to register.
    \item The system must permit universities to register.
    \item The system must allow users to log in by inserting their credentials.
    \item The system must allow student to publish his CV.
    \item The system must allow companies to publish internships.
    \item The system shall inform students when suitable internships are available through recommendation. %specify that this is an out assumption on how the system provides recommendations --> point to specific section
    \item The system shall inform companies about the availability of student CVs corresponding to their needs, through recommendation. %specify that this is an out assumption on how the system provides recommendations --> point to specific section
    \item The system must use analysis produced by the statistical analysis tool to formulate recommendation for students and companies.
    \item The system shall provide suggestions to companies for the project description.
    \item The system shall provide suggestions to students regarding their CVs.
    \item The system shall allow the company to select the students, among all candidates, for the internship.
    \item The system must collect feedbacks from students and companies in order to keep statistics up-to-date.
    \item The system must send feedbacks to the statistical analysis tool in order to update its analysis.
    \item The system must allow the student and the company to monitor the execution and the outcome of the matchmaking process. %specify allow the student to see if his candidature is accepted and then he could proceed with an interview or he isn't selected
    \item The system must allow the student, the company and the university to monitor the ongoing internship. %specify ("By looking on reports")
    \item The system must allow interrupting an internship when university requires it. %we thought that only the university could interrupt the internship and not the company
    \item The system must provide to student all available internships related to the keyword specified by him. %specify that it also involves recommendation (statistical analysis) maybe in case of common keywords 
    \item The system shall inform the company and the student that the internship has concluded cause of the decision of the student's university. %specify due to student complains
    \item The system must prevent students to apply for the internship once the company has selected the eligible candidate for it.
    \item The system shall allow students to modify their CV.
    \item The system shall allow companies to modify internship description.
    \item The system must allow students and companies (that are involved in the same internship) to send messages to each other.
    \item The system must allow students and companies to posts reports regarding internship.
    \item The system must notify the company about the new matching proposal made by the student.
    \item The system shall allow the student to send a matching proposal to a company.
    \item The system must inform the student about a new matching proposal made by the company.
    \item The system must inform the student or the company of the outcome of the matching proposal he sent to the counterpart.
    \item The system shall allow the company or the student to either accept or decline the matching proposal made by the counterpart.
    \item The system must allow future members of the company to add their company to the application by providing a name, a description and a mail domain.
    \item The system must allow future members of the university to add their university to the application by providing a name and a mail domain.
\end{itemize}

% Schedule the meeting
\usecase{
    Schedule the meeting
}
{Company member and the student.}
{The company member and the student are correctly logged in with their chat opened. They agree on the meeting time and where it will be held.}
{
    \begin{enumerate}
        \item The recruiter clicks the \textit{"Schedule a Meeting"} button.
        \item The system displays a form for meeting details (e.g., date, time, location, purpose).
        \item The recruiter fills in the required details and confirms the entry.
        \item The system notifies the student of the scheduled meeting.
        \item The system adds the meeting to the calendars of both the recruiter and the student. If the meeting is online, the system generates a link for the video conference and attaches it to the event.
    \end{enumerate}
}
{The meeting is in the student's and recruiter's calendar.}
{
    \begin{itemize}
        \item The system identifies errors in the scheduled meeting (e.g illegal time frame) and shows a message to the screen.
        \item The system detects an overlap with an event already in the calendar and shows a warning to the user.
    \end{itemize}
}
{}

% Posting a feedback.
% Even when an internship is interrupted, it must be possible to write a feedback. In this way, the analyzer will penalize the company from being suggested to students.
\usecase
{Post a feedback}
{
    \begin{itemize}
    \item Student
    \item Company member
    \end{itemize}
}
{
    The student or company member is logged into the platform's homepage. 
    The internship is ended.
}
{
    \begin{enumerate}
        \item The user notices the system notification indicating the end of the internship.
        \item The user clicks on the notification.
        \item The system prompts the user with the message \textit{"Would you like to write a feedback?"} and provides \textit{"Yes"} and \textit{"No"} options.
        \item If the user selects \textit{"No"}, the system closes the notification and returns the user to the homepage.
        \item If the user selects \textit{"Yes"}, the system redirects them to the feedback page.
        \item The user writes a comment and rates the internship experience.
        \item The user clicks the \textit{"Post"} button to submit the feedback.
        \item The system processes and forwards the feedback to the relevant external tool.
    \end{enumerate}

}
{The user either refuses to write a feedback or posts it}
{The feedback is incomplete, the system shows an error message.}
