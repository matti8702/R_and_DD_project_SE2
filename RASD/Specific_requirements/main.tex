\subsection{External Interface Requirements}

\subsubsection{User Interfaces}

The Students\&Companies platform has a web application interface accessible to all students, company members, and university 
members via an internet browser.

\subsubsection{Hardware Interfaces}

Each user can access the platform from any device equipped with an internet browser and a reliable internet connection. The
 most common devices used to access the system are smartphones, tablets, and computers.

\subsubsection{Software Interfaces}

The system requires the APIs of two external tools: the video conferencing tool and the statistical analysis tool. 
Additionally, it will use a mailing system to verify users and send updates about new recommendations.

\subsubsection{Communication Interfaces}

The system's required communication interfaces include the HTTPS protocol and the Simple Mail Transfer Protocol (SMTP) 
for email handling.


\subsection{Functional Requirements}
Below there are the functional requirements that the system must guarantee.

\begin{listInSquareBrackets}{R}
    \item The system must permit students to register by providing their personal information and an institutional email.\footnote{"Institutional email" stand for the email assigned to the student by their university.}
    \item The system must permit company members to register.
    \item The system must permit universities members to register.
    \item The system must permit universities members to register their universities.
    \item The system must permit companies members to register their companies.
    \item The system must allow users to log in by inserting their credentials.
    \item The system must allow student to publish their CV.
    \item The system must allow companies members to publish internships.
    \item The system shall inform students when suitable internships are available through recommendation.
    \item The system shall inform companies members about the availability of student CVs corresponding to their needs, through recommendation.
    \item The system must use analysis produced by the statistical analysis tool to formulate recommendations for students and companies.
    \item The system shall provide suggestions to companies members for the project description.
    \item The system shall provide suggestions to students regarding their CVs.
    \item The system shall allow the company members to select the students, among all candidates, for the internship.
    \item The system must collect feedbacks from students and companies members in order to keep statistics up-to-date.
    \item The system must send feedbacks to the statistical analysis tool in order to update its analysis.
    \item The system shall allow the company member to schedule a meeting with a candidate.
    \item The system must allow the student, the company members and the university members to monitor the ongoing internship.\footnote{The monitoring is achieved through report visualization.}
    \item The system must allow interrupting an internship when university members requires it.\footnote{Only university members could interrupt the internship and not company members.}
    \item The system must provide to student all available internships related to the keyword specified by him.
    \item The system shall inform the company members and the student that the internship has concluded cause of the decision of the student's university.
    \item The system must prevent students to apply for the internship after closing the application period. 
    \item The system shall allow students to modify their CV.
    \item The system shall allow companies members to modify internship description.
    \item The system must allow students and companies members (that are involved in the same internship) to send messages to each other during the selection of the candidates.
    \item The system must allow students and companies members to posts reports regarding internship.
    \item The system must notify the company members about the new matching proposal made by the student.
    \item The system shall allow the student to send a matching proposal to company members.
    \item The system shall allow company members to send a matching proposal to students.
    \item The system must inform the student about a new matching proposal made by the company members.
    \item The system must inform the student or the company member of the outcome of the matching proposal he sent to the counterpart.
    \item The system shall allow the company members or the student to either accept or decline the matching proposal made by the counterpart.
    \item The system must allow company members to delete an internship only when it is closed for applications.
    \item The system must enable students to accept or decline offers after being selected to start the internship.
    \item The system must allow students to post complaints.
\end{listInSquareBrackets}

\usecase
{Registration of a university member}
{
    \begin{itemize}
        \item University member
        \item EMail provider
    \end{itemize}
}
{
    The university member clicks on button \textit{"Register as a university member"}.
}
{
    \begin{enumerate}
        \item The system shows the \textit{"Registration form"}.
        \item The university member enters his name, surname and date of birth, a password and his institutional email.
        \item The university member selects his university amoung all the universities registered to the system.
        \item The university member clicks the button \textit{"Register"}.
        \item The system verifies that the email is associated to the university provided.
        \item The system verifies that the email is not already registered to the system.
        \item The system sends an email to the university member by an eMail provider.
    \end{enumerate}
}
{
    The university member verifies the email provided to the system by following the instructions on the email message that he received.
}
{
    \begin{itemize}
        \item The email is already registered to the system. The system will show an error message \textit{"User already registered"} and it will interrupt the registration process.
        \item The email provided is not linked to the university provided by the member. In this case the system will show an error message \textit{"Invalid email domain"}.
        \item The university in which the university member works is not present in the system. In this case the university member clicks the button \textit{"Create your university"} and by clicking it the system will show the \textit{"University registration form"} in which the university member will enter all the information regarding the university. Once he has confirmed all data, the institution will be inserted to the system and moreover it will sends a confirmation email to the university member.
        \item The member does not confirm their email address within one day of entering the data into the system. In this case the system will delete all provided data. The member will then need to repeat the registration process.
    \end{itemize}
}

\subsection{Performance Requirements}
\subsubsection{Response time}
The system's response time must be minimized to ensure an optimal and seamless user experience, even during peak load periods.
\subsubsection{Scalability}
The system must be scalable to ensure continued functionality in the future, following an increase in users. As an application that could potentially be used by the majority of students and companies, the system must be able to handle a growing number of users without compromising performance. Scalability must be ensured both horizontally and vertically.
\subsubsection{Data volume}
The system must support the permanent storage of user information for a large number of students from various universities and company/university members. It should ensure high performance and responsiveness, even as the volume of stored data grows significantly.
\subsubsection{Latency}
The latency of communication with external tools (e.g., video conferencing tools and statistical analysis tools) and with end-user devices must be low, ensuring a seamless user experience. The maximum acceptable latency for critical operations should be below 200 ms. An example of a critical operation is sending the communication of internship termination, due to the student's university decision.

\subsection{Design Constraints}

\subsubsection{Privacy Complaints}
All users' sensible information must be handled accordingly to existing regulations (e.g GPDR).

\subsubsection{Hardware limitations}
\begin{itemize}
    \item Web Application
        \begin{itemize}
            \item Internet connection
            \item Device with a display
            \item Web browser  
        \end{itemize}
    \item Backend
        \begin{itemize}
            \item Scalable webserver
            \item Database Management System
        \end{itemize}
\end{itemize}

\subsection{Software System Attributes}

\subsubsection{Reliability}
The system must be fault and byzantine tolerant to prevent the system from propagating erroneous information to the user and along the internal components. 

\subsubsection{Availability}
The system must be as available as possible, with a minimum value of 99.9\% of time.
It shall prevent maintenance break during the day, limiting such breaks only at nightime when it is unlike to have users interacting with the platform.

\subsubsection{Security}
The system must validate any user accessing the platform, always verifying the permissions of each user's operation.
Measures to protect the database from malicious attacks must be adopted.
The user's personal data must be encrypted.

\subsubsection{Maintainability}
All the code produced should be well commented and tested.
The system structure should provide the ability to deploy updates in the backend without the user noticing it.
System components should be created to be as modular as possible. 

\subsubsection{Portability}
The system must be accessible by the Users from every kind of Web Browser.
